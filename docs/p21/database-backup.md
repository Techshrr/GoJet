# 原生数据库一致性备份

对应主计划 §4.1、§4.2 与 P21-T014。`DatabaseBackup::create(connection, directory)`
是可信 root 升级执行器使用的内部组件，没有新增网页端点或生产恢复命令。

`connection` 沿用本地数据库配置：host 固定为 `127.0.0.1`，port、name、user、password
显式提供。密码不接受控制字符。目标必须是已有 root 所有、0700 的可信父目录中的
全新目录；已有目录、符号链接和上次失败的目录均不得覆盖。备份账号需要连接权限、
导出数据库对象的权限及 `mysqldump --lock-all-tables` 所需权限；组件不会自动提权。

组件先确认实际 MySQL 8，再使用系统 `/usr/bin/mysqldump` 执行全局读锁一致性导出，
包含表、数据、触发器、存储过程和事件，二进制数据按十六进制导出，关闭 GTID 写入。
**导出期间全局读锁会阻塞该 MySQL 实例上的写入**，必须安排维护窗口，并考虑同实例
其他数据库；执行最长 300 秒，超时终止导出并释放其连接持有的锁。

凭据仅短暂写入 root 私有配置文件，不出现在进程参数中；完成或常规失败后删除。
进程被外部强制杀死时可能留下私有凭据/部分 SQL，须由 root 检查和清理，不能当作
可用备份。目标目录 0700，SQL 和记录 0600；这些文件含业务隐私，不能上传到 CI
公开附件、提交 Git 或放入发布包。CI 仅上传脱敏的验证结果。

仅导出进程成功退出、没有诊断、SQL 完成 fsync 且凭据已删除后，才写入 `complete.json`，
记录数据库名、server UUID、字节数、SHA-256 和一致性方式。失败保留部分 SQL，移除成功
记录；重试必须使用新目录。原始错误和 SQL 不写入组件异常消息。

`restore_verified=false`、`upgrade_authorized=false` 始终保留。备份文件及其摘要不是
独立可信签名，也不能证明与某个发布包绑定：升级执行器仍须将此备份绑定到当前已验证
的 release/config，并在使用前重新核对摘要和私有权限。

现有原生迁移 CI 新增真实恢复演练：应用全部 31 项迁移，加入二进制、NULL、中文测试数据，
导出后导入独立测试库，比较每张表的完整校验值、触发器定义、测试数据以及迁移日志可用性。
另验证旧备份保护、错误凭据、导出权限不足时不生成成功记录。该演练只操作临时测试库，
不提供生产恢复授权。生产恢复编排、配置/文件存储备份、版本兼容性、原子切换和健康检查
仍须完成，不能凭本组件宣称 T014 或 G11 通过。
