# 原生主机预检

本项对应总计划 §4.1 的操作系统支持矩阵、CPU、磁盘和权限要求。

安装器在既有八项依赖检查外增加 host 项。主机身份只能来自 /etc/os-release、当前内核架构和 PHP 整数宽度，
请求参数和环境变量不能覆盖它。当前支持 Ubuntu 24.04、Linux x86_64、64 位 PHP；发行版小版本仍以 VERSION_ID=24.04 为准。
缺少、重复、不可解析或不受支持的身份信息拒绝通过；不执行 os-release 内容。

已验证的 manifest 提供所有归档文件大小。发布目录所在文件系统须至少另有一份完整解包内容的空间；
存储根目录、quarantine、published 各自所在文件系统须有可用空间，不能只检查根分区。
这不是业务容量或数据库备份大小估算，不增加规范未声明的 CPU 核数或内存门槛。
原有非 root 存储写入、目录权限及 ClamAV 检查继续独立执行。

host=false 会令预检 ready=false，并通过既有安装准备校验阻止数据阶段、阻止健康确认和完成锁。
升级准备/切换后的健康检查也调用同一预检。浏览器仅展示 root 发布的短期快照，显示失败原因分类，
不会因页面显示通过而跳过实际执行前复查。旧的八字段快照不满足新的完整字段集合，不能被当作当前健康证明。

## 验证设计与边界

六个原生负例：错误发行版、错误发行版本、空身份文件、linux32 CPU personality、发布目录空间不足、存储空间耗尽。
每个负例单独在私有 mount namespace 执行。错误身份文件为测试输入；真实 PHP 解析这些文件，不替换生产判定函数。
容量场景使用真实 tmpfs 和实际填满文件系统；不是返回伪造的 disk_free_space 值。

容量受限的副本绑定到原路径，仅对当前预检进程可见；systemd 的非 root helper 仍看到主机原始健康路径。
因此这些用例明确验证 host 项拒绝并保持其余八项健康，不把它们冒充非 root helper 的 ENOSPC 测试。
命名空间退出后原始主机身份、发布包和存储不变；全部场景不执行迁移、不创建 installed.lock。

PHP 身份解析单元测试覆盖重复键、空值、命令文本、错误系统/架构/位宽及超长输入。
桌面/移动浏览器测试覆盖新增第九项及 host 失败显示；快照夹具只作为 UI 证据，不能代替上述原生拒绝。
