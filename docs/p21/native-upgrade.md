# 原生升级与恢复（原生集成验证通过）

本批代码已通过原生 CI 整体验证；下文为测试环境操作说明，不是生产发布授权。
两个正式版本间的升级、目标系统及正式发布验收仍待完成，不能据此关闭 T014/G11。

## 整体流程

`prepare-upgrade.php CURRENT_PREPARED CANDIDATE MANIFEST_SHA256 SOURCE JOB` 从标准输入
读取专用数据库管理员连接信息，验证当前安装或上一升级记录、两份包、迁移历史和版本边界。
管理员凭据仅进入 root 私有计划；业务服务环境和密钥沿用原值，不重新初始化管理员。
目前只接受 10.0.0 正式版及其 rc 版本，拒绝版本倒退、迁移历史删除或重写；不授权任意 10.x 跨版本升级。

准备结果给出计划摘要。`run-upgrade.php JOB PLAN_SHA256` 持有独占升级锁，依次进行：

1. 保存执行屏障，关闭公网业务访问，停止全部八个写入服务。
2. 把原有 systemd/Nginx 文件接入版本化配置快照；未知文件和外部链接拒绝接管。
3. 备份数据库、文件存储和版本配置，记录私有摘要。
4. 在独立临时库实际恢复 SQL，核对所有表校验值和触发器；失败禁止迁移。
5. 再核对迁移历史，持原迁移锁执行迁移。
6. 原子切换配置指针，检查及重载 Nginx，加载并启动八个服务。
7. 验证包、依赖、服务非 root 身份和实际可执行文件、前端内容、TLS、API 与安装器关闭状态。
8. 先提交新版本权威记录，再开放公网；等待不带维护令牌的完整健康检查稳定通过后，才清理屏障。

维护探测同时要求回环来源和 root 私有随机令牌；只有回环来源或伪造转发头不能放行。
令牌及维护配置均为 root 0600。独立真实 Nginx 测试和完整 systemd 升级恢复测试均已通过。

## 中断和恢复

每次有副作用的阶段开始前保存状态。`recover-upgrade.php JOB PLAN_SHA256` 要求同一份私有计划：
迁移开始前中断恢复旧配置；迁移开始后中断先恢复数据库及文件，再恢复旧配置和旧服务。
只有旧版本健康检查通过，才开放公网。恢复会替换目标数据库；原备份、阶段记录和被替换的文件树保留。
恢复前先验证数据库及文件两份备份，恢复后比较表结构、数据校验值和触发器。不会保留被替换的候选数据库。

`committed` / `recovery-committed` 表示数据及服务验收已提交，此后中断只完成开放访问和屏障清理，
不得再次还原数据库而丢失已开放后的写入。未知阶段、缺失屏障、外部改写的当前版本都拒绝继续。
原首次安装完成锁保持不变，新的版本权威单独保存在 `/var/lib/gojet-upgrade-authority/`。

## 测试环境操作顺序

以下命令供隔离测试环境复核，不构成生产部署授权。使用原版本中经过校验的升级工具；
候选版本损坏时仍使用这份原工具执行恢复。所有命令在 root 会话执行，先设置 `umask 077`。

事先提供这些经过核对的绝对路径或发布绑定，不能从未经确认的候选文件自行推导信任：

| 变量 | 内容 |
| --- | --- |
| `CURRENT_RELEASE` | 当前已校验的发布目录，保留至升级及恢复验收结束 |
| `CURRENT_PREPARED` | 原首次安装的 sealed 准备目录 |
| `CANDIDATE_RELEASE` | 独立的候选发布目录，不覆盖当前目录 |
| `CANDIDATE_MANIFEST_SHA256` / `CANDIDATE_SOURCE` | 已批准候选的 manifest 摘要和源码 SHA |
| `UPGRADE_JOB` | root 所有、0700 父目录下尚不存在的新任务目录；与发布、数据和准备目录互不包含 |
| `ADMIN_CONNECTION_JSON` | root 私有 0600 JSON 文件，包含 `host`、整数 `port`、`name`、`user`、`password`；host 固定为 `127.0.0.1`，库名和端口须与当前配置一致 |

凭据不放在命令行、聊天或 CI 日志中。当前实现需要专用管理员具备导出、创建演练库以及删除、
重建原库的权限；运行器不会为自己授予这些权限。MySQL 和 Redis 均须先通过当前依赖检查。

```sh
umask 077
php8.3 "$CURRENT_RELEASE/installer/bin/prepare-upgrade.php" \
  "$CURRENT_PREPARED" "$CANDIDATE_RELEASE" \
  "$CANDIDATE_MANIFEST_SHA256" "$CANDIDATE_SOURCE" "$UPGRADE_JOB" \
  < "$ADMIN_CONNECTION_JSON"
```

只有命令成功退出且结果 `prepared=true`，才记录其返回的 `plan_sha256` 为 `PLAN_SHA256`。
准备不执行迁移或停止服务。准备失败时保留已生成目录，处理原因后改用新任务目录；
不把不完整准备交给执行或恢复命令。保留成功准备的摘要，随后执行：

```sh
php8.3 "$CURRENT_RELEASE/installer/bin/run-upgrade.php" "$UPGRADE_JOB" "$PLAN_SHA256"
```

成功退出且 `upgrade_complete=true` 才表示本次升级完成。非零退出、终端断开或进程被杀死时，
保留任务目录、SQL、文件备份、配置快照和原发布目录，使用同一摘要显式恢复：

```sh
php8.3 "$CURRENT_RELEASE/installer/bin/recover-upgrade.php" "$UPGRADE_JOB" "$PLAN_SHA256"
```

恢复成功返回 `recovered=true`；如果升级已经提交，则只完成收尾并返回 `upgrade_complete=true`，
不会倒退数据库。若恢复再次中断，重复同一恢复命令；不要删除阶段记录、执行屏障或迁移历史，
不要手工打开维护门、仅切回二进制或重启写入服务。命令拒绝时保留现场，由 root 检查私有阶段记录；
不得把计划、凭据、SQL 或原始业务数据上传为公开诊断附件。

## 支持边界

文件快照限制为 1 GiB、100000 项，仅接受普通文件和目录。风险缓存扫描限制 100000 个匹配键与
60 秒；超过限制会保留失败屏障，不跳过恢复。数据库仅支持原服务器上、固定 utf8mb4 编码的原库，
拒绝自定义视图、事件和存储过程。旧备份回执缺少编码字段时不能用于新增恢复命令。

不得据此关闭 T014/G11，也不改变 installable=false。真实业务外部依赖、风险投影重建完整性、
目标系统重启和 owner-controlled production 验收仍须分别提供证据。
