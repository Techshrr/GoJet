# P09 T024 与受保护安装入口

旧 P09 浏览器环境通过无 TLS、无私有状态的 PHP 开发服务器访问生产入口，并要求
三个安装步骤直接返回 `step-pass`。P21 入口已要求 TLS、会话和阶段权限；继续使用
该环境会在启动检查失败，导致 T021–T025 均无法执行。

当前测试接入使用生产 `NativeWebConfig` 渲染的 Nginx/专用 PHP-FPM，隔离的私有
状态和 root authority。Python 独立验证临时证书，Chromium 通过真实网页登录。
没有新增生产路由、浏览器请求拦截或 HTTP 测试控制接口。

冻结测试计划及其三个路径均保留。当前受保护接口的验证映射如下：

| 路径 | 未登录 | environment 阶段 | services 阶段 |
| --- | --- | --- | --- |
| `/install/environment` | 401 | 200，显示配置入口，不宣称检查通过 | 409，禁止越阶段 |
| `/install/services` | 401 | 409，禁止提前访问 | JSON 200，读取 root 健康快照；直接 HTML 导航仍 409 |
| `/install/health` | 401 | 409，禁止提前访问 | 409，不伪造整体安装健康成功 |

现有交互安装页读取受保护的 `/install/services` JSON，展示真实 P09 检查结果：

- 原生 `filepreflight` 与测试平台服务使用相同的非 root 用户及存储、ClamAV 配置。
- 正常场景要求实际存储可写、ClamAV 引擎和签名健康。
- 连接到保留但未监听的 loopback 端口，验证扫描器不可用；临时改变真实存储权限，
  验证存储不安全。每次都执行原生检查并恢复现场。
- root 使用生产 `PreflightSnapshot::publish` 发布实际结果。其余六项 P21 检查
  未在此执行，明确保留为 false；P09 两项通过不能使整体安装显示 ready。
- 桌面和手机检查逐项结果、错误详情脱敏、缺失/过期快照清除、恢复、布局和浏览器
  错误；确认观察过程没有安装 POST、草稿、mailbox 或阶段推进。
- root 完成标记存在时，所有三个路径和登录入口都必须返回 404。

两个起始阶段和最终关闭标记是明确的测试夹具；健康探测是真实执行。过期场景仅
调整观测时间，不声称执行了 ClamAV 过期签名测试。这里不证明密封审批、实际
privileged apply、完整首次安装或 P17/P22 完成；这些由独立的原生验收负责。

T024 仍通过原来的 `node scripts/p09/browser.mjs --case P09-T024` 运行，结果继续写入
原证据路径并绑定 exact HEAD。工作流仍要求 T021–T025 全部通过。实际运行结果以
当前提交的 CI 为准，本文本身不构成通过证明。
