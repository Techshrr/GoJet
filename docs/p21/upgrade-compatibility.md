## 已实现的边界

支持版本限于 `10.0.0` 与 `10.0.0-rc.N`，N 为 0 至 999999999 的十进制整数，
除单独的 0 外不得带前导零。允许同版本的不同已批准包，允许 rc 序号递增及 rc 到正式版；
拒绝降级、正式版返回 rc、其他 minor/major、beta、构建元数据和非规范版本串。
此白名单只是版本格式及顺序约束，不能替代包审批、迁移兼容性检查和真实升级验证。

当前安装与候选包均须满足：

1. 原有包完整性、来源 SHA、配置及安装权威检查通过。
2. 八个服务和 `filepreflight` 的独立 `--version` 返回值与包内版本、来源、服务名完全一致。
3. `operationsmonitor --upgrade-capabilities` 返回相同身份和
   `risk_projection_restore="gojet.risk-projection-restore.v1"`。
4. 已应用迁移与旧、新 catalog 的前缀及校验值匹配。

身份和能力探测由 systemd 以 `gojet` 用户执行，不载入业务 EnvironmentFile，
网络隔离、系统目录只读、禁止提权，并有进程时限。能力命令在数据库、Redis 和 worker 初始化前返回。
这项声明只表示程序支持恢复协议，真实恢复仍须通过后续 MySQL/Redis 和整链路检查。

检查在创建任务目录、停止服务、备份或迁移之前完成。失败不生成可执行升级计划；
旧服务继续运行。通过后，将两份探测结果写入私有 `plan.json` 的 `compatibility.old/new`，
随计划摘要绑定。执行时仍重新验证包文件，准备后替换二进制不能绕过校验。
旧包没有能力入口时会明确拒绝准备，不能等到恢复时再发现不支持。

## 验证矩阵

本地版本与报告契约检查已通过。原生 CI 已为以下每个候选重新计算 manifest 和 checksum，
先确认其包完整性通过，再调用真实 `prepare-upgrade.php`；避免把包损坏拒绝误算为兼容性通过。

| 候选情况（当前为 rc.1） | 必须结果 |
| --- | --- |
| rc.0 | 拒绝降级 |
| 10.1.0 | 拒绝未经支持的 minor |
| 11.0.0 | 拒绝未经支持的 major |
| rc.01 | 拒绝非规范序号 |
| beta.1 | 拒绝其他预发布类型 |
| 10.0.0+build | 拒绝未支持的构建元数据 |
| manifest 写 rc.2，实际二进制为 rc.1 | 拒绝版本身份不一致 |
| manifest 来源与实际二进制来源不同 | 拒绝来源不一致 |
| operationsmonitor 位置放入 platformapi | 拒绝服务身份不一致 |
| 二进制有正确版本身份但没有恢复能力入口 | 拒绝不支持恢复协议 |

每次拒绝均核对：没有新任务目录或执行屏障、迁移历史和表清单未变、八服务 PID 未变、
配置文件和首次安装完成锁未变、公开 HTTPS 仍返回 200。随后使用正常候选执行既有完整升级、
MySQL 恢复、209 链接风险投影和 15 个中断/恢复阶段，证明检查没有破坏正常路径。

“没有恢复能力入口”的二进制是独立编译的测试夹具，仅实现离线身份报告，不是已发布旧版本。
正常候选仍沿用同批服务二进制并增加迁移、静态内容，不能据此声称两个正式发布包之间已验收。
