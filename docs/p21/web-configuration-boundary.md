# 完整网页配置的实现边界

状态：实现约束，尚未启用完整配置 HTTP 路由。已批准计划的浏览器提交与 timer 执行
继续使用现有入口；下述缺口完成并验证前，不得把页面表单作为可安装向导发布。

## 输入与权限

| 来源 | 字段 | 约束 |
| --- | --- | --- |
| 服务器 root 预绑定 | 发行目录/摘要、计划目录、状态目录、TLS 文件、存储目录、ClamAV socket、系统 unit 与可执行路径 | 网页不得改写或提交替代值；实际所有权、内容与路径在 root 侧重验 |
| 登录后的网页 | 数据库/Redis 的本地端口与凭据、站点 HTTPS origin、邮件与外部服务设置、配额与文件类型、管理员邮箱/名称/密码 | 只接受明确字段；端口/配置错误不代表检查通过；外部服务凭据不能使用测试默认值 |
| root 私有生成并持久化 | 六个服务密钥及 key ID | 一次生成；刷新/重登/重试不能隐式轮换；不回显至网页或日志 |
| 现有 Go 管理员权限目录 | 初始管理员角色与权限 | 网页不可指定权限、角色 ID、密码散列、MFA 加密密钥或完成状态 |

## 实现顺序与不可跳过的检查

1. **输入校验先于副作用**：NativeConfiguration 继续是配置编译入口；管理员输入调用
   已核验二进制的 `--validate-bootstrap-admin`，与实际创建共用规则。输入错误时
   不发布计划、不执行 DDL、不创建账户。格式校验不等于依赖健康或账户创建成功。
2. **私有草稿转为 root 计划**：网页草稿属于不可信输入，不能直接成为执行授权。
   root 接收时重验所有字段、版本/摘要及预绑定路径，生成和保留私有密钥，再调用
   既有 InstallationPreparation。网页仅持有批准摘要及受限请求，不持有 root 配置。
3. **已验证的执行链继续复用**：只在 root 批准完成后开放提交；复用现有一次性回执、
   实时依赖复检、timer、阶段观察及完成锁。页面状态不能自行授予完成或重试权限。

## 编码前必须同时处理的衔接点

- 当前 HTTP/Nginx 请求上限为 4 KiB，完整 CLI 配置上限为 16 KiB。新增配置路由须
  分步限额并限制合并后的总量，保持登录和执行请求原有小限额；不能仅放大代理限制。
- 当前 `initializePreparedApply()` 用于全新状态目录。草稿审批不能重复初始化已有
  会话或删除失败状态；必须新增受控转换，并验证 CSRF 轮换、并发与断电后的状态一致性。
- 错误字段可给出固定字段名与错误类别，不能回传密码/令牌/原始异常。刷新或重新登录
  不能把已经保存的秘密重新填入 HTML、JSON 或浏览器存储。
- 草稿提交后的连接中断不能触发重复 root 准备；发布中断、已有计划和摘要变化必须
  有确定的拒绝/恢复行为。不能通过删除 started 记录或重新生成密钥来假装重试成功。
- 桌面/手机测试必须使用真实草稿、真实 root 审批及执行；模拟快照只能证明渲染。
  最终验收继续包含账户安全、升级/备份恢复及指定 Ubuntu 24.04.4 目标机验证。


## Root 草稿准备入口（已通过原生 CI）

`installer/bin/prepare-web-configuration.php BINDING` 只在 root CLI 使用：
BINDING 是 root 所有、0600、单链接普通文件，父路径经过安全检查，最多 8 KiB。
绑定字段固定为 `schema=gojet.web-configuration-binding.v1`、`destination`、`release`、
`manifest_sha256`、`source`、`tls` 和 `files`；其中 files 仅有 root/clamav_socket。
这些值由服务器管理员提供，不能从 HTTP 请求中选择绑定文件。

标准输入最多 24 KiB，仅包含 configuration/admin；configuration 沿用既有配置
结构但不得包含 secrets，files 仅允许 max_upload_bytes/max_files/max_bytes/types。
即使提交的受保护路径与 root 绑定完全一致，也拒绝该额外字段；不静默覆盖或忽略。
管理员角色/权限继续由既有原生规则控制。错误只输出固定拒绝信息。

入口组合输入后直接复用 InstallationPreparation::create：核验发行包，检查配置和
管理员输入，生成 root 私有密钥，按原有封存格式原子发布。它只准备计划，不执行
迁移、不启动服务、不写完成锁，也不为网页草稿授予执行权限。原有 root CLI 保留。

原生回归把该入口的成功产物继续交给原有真实数据/服务/浏览器/root timer 测试，
并覆盖客户端受保护字段、非 root、额外参数、错误绑定权限/属主/软链接、错误来源
摘要、重复准备。HTTP 分步收集、CSRF/草稿锁定和 root 审批后的状态转换仍未接入。


## 私有草稿冻结（内部状态接口，待 CI）

InstallState::submitConfiguration 在既有会话、CSRF 和独占锁下接受一个完整草稿。
客户端可提交字段及 24 KiB 序列化上限由 ConfigurationDraft 统一检查，root 准备
入口复用同一检查，语义/原生校验仍由 root 完整执行。无效草稿消耗 CSRF，但不保存
秘密或推进状态；需要重新认证后再提交。

合法草稿先将 environment 状态持久化为 checking，再独占创建和 fsync 私有
configuration-draft.json。响应只有 step/status，状态文件不包含配置秘密。刷新或
重新登录不解除冻结、不覆盖草稿、不创建 apply 请求；写入失败/中断保留 checking
屏障，不能直接重试或删除状态来跳过。此处尚未增加 HTTP 路由或网页表单。

后续 root 审批不得在网页可写目录里重建状态/写入新状态文件；应发布 root 所有的
只读批准记录，由已认证适配层核对草稿摘要后执行受控状态转换。审批绑定、过期与
并发的完整验收仍待实现，不能以保存成功代替批准或安装成功。
