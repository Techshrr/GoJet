# P22 临时主机验收

2026-11-06：负责人已委托 Codex 批准 G11，并提供专用 Ubuntu 24.04 临时服务器。
[G11 PASS](../../artifacts/v10/gates/G11/native-package/decision.json)绑定的原始归档直接用于验收，不重新构建。
主机登录凭据和公网地址只保留在私有接入上下文，不进入公共仓库、命令日志或截图。

## 当前执行状态

当前执行环境默认 SSH 配置因权限检查失败；使用 `-F /dev/null` 隔离该配置后，TCP 22 连接立即返回 `Network is unreachable`。
尚未到密码认证，没有执行任何远程命令、安装依赖、重启服务或整机重启。
这证明当前执行环境无法建立连接，不证明服务器关闭或口令错误。
接入记录见 [connection.json](../../artifacts/v10/P22/connection.json)。继续实机执行需要能连接该服务器的执行环境或可操作的服务器控制台入口。

## 接入后的第一步

先在主机以 root 执行仓库中的 `python3 scripts/p22/host_inventory.py`，私有保存完整 JSON 输出。
脚本只读取 OS、架构、PID 1、boot ID、主机标识摘要、磁盘、已安装原生依赖、服务、监听端口和固定状态路径是否存在。
它不读取密码、进程环境、数据库内容或私钥，不自动确认主机干净，也不安装软件或改配置。
当前仅在工作环境验证了脚本执行及不完整清单拒绝；没有目标机执行结果。
输出可能包含主机监听地址和自定义服务名称，入库前脱敏，并保留私有原件与摘要。

对照负责人声明检查现有状态；有未知数据或业务服务先保留现场，不清库、不覆盖。
真实 Ubuntu 24.04 补丁版本、amd64、systemd PID 1 和干净状态确认后才安装手册要求的原生依赖。
不要将脚本零退出或机器清单当作 G12 通过。

## 一次连续执行

[test-plan.json](../../artifacts/v10/P22/test-plan.json)列出合同、预期结果和记录要求；各项初始均为 NOT_RUN。
每一阶段保存开始/结束时间、命令退出码、候选身份、脱敏 HTTP/终端/服务记录，浏览器操作保存实际截图。
重启前将检查点写入主机 root 私有目录并保存到执行端；重连后比较主机标识摘要和不同 boot ID。
失去连接或执行会话不能判为通过；从已记录阶段恢复，不能重新初始化已有安装。

1. 检查干净主机，下载并验证 G11 指定归档及 manifest，再按包内手册准备依赖与独立配置。
2. 逐项验证九项预检的失败拒绝与恢复，确保失败不迁移、不生成完成锁。
3. 从真实 HTTPS 浏览器安装入口连续执行配置、root 审批、apply、八服务健康、完成锁与入口退役。
4. 记录八 unit enabled/active/非 root PID，restart 后验证；整机 reboot 后重连同一主机，再验证全部健康和 P0 smoke。
5. 完成 Nginx 原子回退、MySQL 真实备份还原、Redis 重连与风险缓存重建、ClamAV clean/EICAR。
6. 使用身份明确的兼容候选执行升级故障恢复及必要数据库回滚，验证恢复后的八服务、配置、数据与 P0。
7. 归档 G12 证据后进行责任复核。G13 真实生产外部依赖另行接入与授权，不能用测试替身或临时机结果代替。

操作入口沿用 [首次安装](../release/install.md)、[运维](../release/operations.md)、[升级与恢复](../release/upgrade-recovery.md)。
