# 完整交付包验收约束

不得以构建成功、服务启动或页面不报错替代完整安装/业务验收。
最终交付包绑定同一提交、原生归档摘要、manifest 摘要及每份测试报告。
所有验证在开发/CI 环境完成，不要求操作员持有按小时计费的主机等待修复。

## 构建门槛

1. 冻结依赖构建四个前端和九个原生可执行文件；验证身份、归档可复现性、文件清单和篡改拒绝。
2. 使用交付的 stage-release.py 在 umask 077 下真实解包，再通过目标 PHP 校验；不得靠后补 chmod 脚本修复。
3. 对安装入口、首次安装完成和升级健康检查分别验证 CA 签发证书链、错误域名和不受信任证书，不修改全局 PHP 配置。
4. 空白 Ubuntu 24.04/systemd 环境安装实际候选：浏览器配置、root 任务、数据库迁移、八个业务服务、Nginx TLS、安装入口退役。
5. 新版迁移目录驱动恢复测试，故障迁移编号在真实迁移之后生成；覆盖部分 DDL、多个中断阶段、恢复中断和提交后数据保护。
6. 另一个干净 runner 安装原始、摘要固定的 rc.1 归档，再升级到当前候选的实际二进制；迁移后中断必须恢复旧 schema、设置和文件，再成功提交新版本。
7. 桌面 1440px 和移动端 390px：原生管理员 Cookie、权限撤销、Origin/CSRF、TOTP、设置保存及后台页面。Jobs 测试真实空列表，Services 测试八个固定服务条目，不能编造空服务状态。

报告只允许列出实际执行通过的项目；错误或缺失报告必须阻止最终打包。
私有连接、数据库快照、证书私钥、Cookie、TOTP 秘钥不进入 CI 制品。

## 尚不能由上述测试证明的范围

- 实际主机重启后的验收（普通 runner 内重启服务不等于整机重启）。
- 当前站点外部 SMTP、Turnstile、Google 配额/密钥/DNS/证书以及真实业务操作。
- 支付收款和外部邮件投递；CI 不发送真实邮件、不执行真实支付。
- 自定义数据库对象、非受支持系统、其他版本跨度和任意混合部署。

未满足发布要求时保留候选状态，不提供所谓“最终完善包”。
