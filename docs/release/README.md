# GoJet 原生候选包操作手册

本目录随不可变发布包交付，适用于 Linux amd64 原生部署。先读[安装](install.md)，日常维护见[运维](operations.md)，版本切换及故障处理见[升级与恢复](upgrade-recovery.md)。命令面向有权限的主机操作员；示例变量必须从本次经审核的发布记录和主机私有记录取得。

## 发布边界与交付物

| 项目 | 包内位置或随包证据 |
| --- | --- |
| 八个原生服务及文件预检助手 | bin 目录；运行身份和版本以 manifest.json 为准 |
| 四个编译后前端 | static/site、static/docs、static/workspace、static/admin |
| 原生配置与启动资产 | deploy 目录；安装器根据密封配置生成实际部署文件 |
| 数据库迁移及顺序 | migrations 目录、migration-catalog.json |
| 安装、升级、恢复入口 | installer/bin 目录 |
| 内容清单、依赖与校验 | manifest.json、sbom.cdx.json、SHA256SUMS |
| 操作手册 | 本目录四份文件，纳入清单、SBOM 和校验和 |
| 候选验收索引 | 构建附件中的 candidate.json，与归档分开保存，绑定归档和原始测试报告摘要 |

当前包仍明确标记 `payload-only-not-installable`、`installable: false`。测试环境链路通过、生成 candidate.json，均不自动授予 G11 审批或生产部署权限。P21 完成资产和技术评审；P22/G12 验证目标洁净主机安装和重启；P22/G13 需要负责人批准及真实外部服务、域名等生产验收。没有“两份历史正式版本必须先存在”的前提。

## 证据与信任

从经批准的发布记录独立取得源码提交、归档 SHA-256、manifest SHA-256；不要把同一未验证下载内的校验和当成独立信任来源。candidate.json 是可审查的证据目录，不是签名、批准或可信下载通道。归档确定后不得修改或重新打包；任何内容变化均须新候选和新证据。

构建检查手册中的包内文件引用、相对链接及 shell 语法，不会执行操作员命令。原生 CI 独立验证安装、八服务、TLS、MySQL 恢复、Redis 风险投影和升级中断恢复；证据中的范围限制仍有效。同一候选二进制构造的升级夹具不证明任意历史版本兼容，也不代替目标生产环境验收。

## 操作约束

先在测试主机演练，再按维护窗口审批操作目标主机。保留旧版本、私有配置、密封记录和经演练的备份。禁止手工删除锁或日志来绕过失败、覆盖现有服务配置、仅回退二进制而保留不兼容数据库，或把数据库口令放在命令行、URL、工单或公开日志中。凭据文件仅 root 可读，相关目录应为 0700、文件为 0600；不要开启 shell 跟踪。
